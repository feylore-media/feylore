# Clubs revision implementation

The September 15, 2026 scope decision promotes the supplied revision into V1. The accepted design reference is [book_club_view.txt](book_club_view.txt); the migration mapping is [CLUBS-REVISION-AUDIT.md](CLUBS-REVISION-AUDIT.md).

## Foundation milestone

Implemented:

- Separate `club_reads` occurrences with canonical Work references or external candidate snapshots; scheduled/active/completed/cancelled lifecycle; one active and one scheduled read per club; dates; creator; originating selection round; cursor-based history. A completed/cancelled occurrence cannot be reopened as a reread.
- Separate selection rounds, candidates, nominations and ballots. Configuration covers independent dates, nomination allowance, method, tie behavior, previous-read exclusion and result visibility. Methods/rules freeze after nominations open; dates may be extended through the configuration endpoint.
- Authenticated member nomination/ballot ownership, nomination limits serialized under a round lock, candidate validation, and exact participation deadlines. Opening rounds and read lifecycle operations lock the club to coordinate competing requests.
- Simple polls, deterministic instant-runoff counts/transfers/exhaustion and recorded elimination tie rules, moderator/random tie resolution, and separate runoff rounds with fresh ballots. Final random draws persist the eligible pool, configuration, decision timestamp, winner and resulting scheduled read. Repeated finalization returns the stored result.
- External manual candidates require title/author; no canonical Work or file is created. Candidate metadata is a snapshot. Manual nomination provenance/warnings are attributed to the authenticated user. Common content-warning and media-location schemas live outside the Club domain.
- Shelf candidate import delegates membership/rule evaluation and access to the Shelf service. Previous completed-read exclusion is checked again when selecting; eligible IDs used by a draw are persisted.
- Legacy Current Work writes mirror into read occurrences transactionally. Completed history survives promotion of the same Work association into a reread. New canonical active/scheduled reads retain compatibility with old Work consumers. These operations never update personal progress or ratings.
- Read-specific schedule identity propagates into occurrences and generated topics. Club-wide schedules remain valid with no read. Invalid/cross-club/closed read references are rejected when creating schedules; closed reads do not materialize further occurrences.

## Migrations

`0036_clubs_read_selection_foundation.sql` adds the new tables and nullable read/location references. It backfills current and completed Work associations, the first queued Work per club, existing poll candidates/ballots and scheduled-topic associations. Extra queued Works remain in `club_works`. Unscheduled discussions/quotes stay club-wide rather than being assigned to a historical occurrence by guesswork. Unknown read/completion dates remain null.

Legacy polls, options, votes, Works, schedule/occurrence IDs and topics are retained. Candidate snapshots capture metadata available at migration time; later canonical title edits do not mutate them. Historical poll results retain their winner and legacy timing markers; original votes remain available in copied ballots.

`0037_club_read_compatibility_constraints.sql` also supports environments that applied an early foundation draft: remove the legacy association uniqueness restriction and use NO ACTION references to preserve direct-read integrity while permitting whole-club cascades. Multiple read occurrences may refer to the same legacy Work association.

No legacy routes or tables have been removed. At this foundation checkpoint poll routes remained a compatibility interface; the final compatibility disposition is recorded below.

## New API

All paths use the existing `/api/v1` prefix. Reads require `clubs.read` and club visibility; mutations require `clubs.write` and either club moderation or authenticated membership as appropriate.

| Method | Path | Behavior |
| --- | --- | --- |
| GET | `/clubs/:id/reads?cursor=…` | Up to 50 read occurrences and next cursor |
| GET | `/clubs/:id/reads/current` | Active occurrence or null |
| GET | `/clubs/:id/reads/:readId` | Authorized occurrence |
| POST | `/clubs/:id/reads` | Create canonical/external occurrence |
| PATCH | `/clubs/:id/reads/:readId` | Update dates / permitted lifecycle transition |
| GET | `/clubs/:id/selection-rounds` | Recent round history |
| GET | `/clubs/:id/selection-rounds/current` | Open round, otherwise latest round |
| GET | `/clubs/:id/selection-rounds/:roundId` | Candidates, participation, viewer ballot and permitted results |
| POST | `/clubs/:id/selection-rounds` | Create a configured draft |
| PATCH | `/clubs/:id/selection-rounds/:roundId` | Configure draft / extend dates |
| POST | `/clubs/:id/selection-rounds/:roundId/transition` | Manual open/close/cancel transition |
| POST | `/clubs/:id/selection-rounds/:roundId/nominations` | Member nomination |
| POST | `/clubs/:id/selection-rounds/:roundId/ballot` | Submit or replace own ballot |
| POST | `/clubs/:id/selection-rounds/:roundId/shelf` | Import an authorized Shelf pool |
| POST | `/clubs/:id/selection-rounds/:roundId/finalize` | Persist result / create upcoming read / create runoff |

`POST /clubs/:id/schedules` additionally accepts optional `clubReadId`. The legacy `clubWorkId` continues to work and resolves to an ongoing occurrence where one exists.

Current member presence uses the newest canonical `reading_progress` row for the active Book Work, with `user_progress` as fallback. Only coarse percentage, numeric chapter/page and finished state are projected. Chapter titles, reading sessions, representation IDs, private Journal text and detailed timestamps are absent. External active reads report unknown progress. No active read omits progress. Read participation is unchanged: a read-specific topic, reply, explicitly shared passage or occurrence check-in establishes participation. Current membership and read creation alone do not. External reads with no canonical progress do not count as personally finished.

Stats includes completed Club Reads only. Known pages and length calculations use positive page counts in read snapshots, with the number of known page counts shown. Duration uses only reads with both start and completion dates; missing values never contribute zero. Typical length and duration are medians. Typical participation is the median read-specific participant count across completed reads, including reads with no recorded participation. Completion, check-in and discussion numerators refer to participant occurrences; the denominator is all evidenced participant occurrences on completed reads. Genre counts allow multiple labels per read and resolve configured aliases and parent terms through the shared metadata vocabulary. Untagged reads are excluded from genre counts.

Core and configured genre dimensions require two contributing review values; trajectory interpolates only inside a contributor's recorded range and requires two contributors per point. The one historical trend groups dated completions by month. **Historical rating limitation:** completed read aggregates use participants' current authoritative finalized rating records. A later rating edit can change a historical aggregate; V1 has no occurrence rating snapshots.

Creation resolves the durations to concrete timestamps and copies all rules into the round; partial configuration overrides preserve the other defaults. A default random draw has no voting phase and can resolve when nominations close; explicitly supplied voting dates remain valid. A later default edit leaves every existing round unchanged, including frozen and historical rounds. Manual early opening or closing records the actual phase boundary so authenticated participation and date order remain valid. Random draw has no meaningful tie or during-voting visibility setting; saving that method normalizes both. Check-in cadence and final-discussion creation remain deliberate schedule actions because they require a consumption target and read-specific timing; no parallel schedule model was added.

The worker's existing hourly Club sweep now also scans Selection Rounds on startup and each tick. It pages through persisted rounds and advances only due deterministic boundaries: draft to nominations open, nominations close, voting open, and finalization at the voting deadline. A random draw without voting dates can finalize when nominations close; a draw with voting dates waits for the voting deadline. The sweep calls the same locked transition and finalization methods as the moderator API. It catches expected conflicts from competing actors, retries on the next sweep, and cannot create a second result or draw once a round is completed. It stops if candidate/ballot validation fails, a moderator tie needs a decision, or a new read cannot be scheduled. Configured runoff uses the existing new-round result operation; its fresh voting phase has no automatic closing date until configured. Cancelled/completed rounds are ignored. Multiple missed boundaries are processed in one pass after downtime. There are no per-round timers or browser-driven phase writes.

Migration 0043 identifies a one-time, read-linked final-discussion schedule separately from check-ins. The shared `ClubUpcomingService` derives stable `kind:source-id` event identity from current/scheduled read dates, active schedule occurrences and active Selection Round deadlines. Moving a source date moves that event; cancellation, completed reads/rounds, paused schedules and closed occurrences remove future projections. It includes external read snapshots without requiring a canonical Work or file. `GET /upcoming` uses a domain-neutral Upcoming response and queries only public Clubs or Clubs where the authenticated viewer remains a member; Overview uses the same Club projection. Global Upcoming is presented on Home. Its current production feed contains Club events; other media domains have not yet supplied dated event providers. Club names and read titles never enter an unauthorized private-Club response. Events are bounded to the next 90 days and 30 global or eight Overview items. Final discussion is sourced from an explicit schedule occurrence, not inferred from the target end date.

Legacy `club_polls`, options and votes remain for migrated history and old API callers. The old Poll manager is absent from new Settings. A published or closed legacy poll blocks new Selection Round creation until resolved. Once a Club has created a non-legacy Selection Round, legacy poll publication and result application are blocked even after that round completes; publication and new-round creation serialize on the Club row. Legacy votes/options remain writable for an already active legacy poll in a Club that has not entered the new workflow, and an applied legacy result still reaches Club Reads through the Work compatibility path. Poll routes and tables remain in place; removal is a future migration. `club_works` remains a canonical Work association/current/queue compatibility model. Its Current Work mutations mirror into `club_reads` in one transaction; completed/cancelled occurrences remain history and rereads create new occurrences. Extra queued Works can stay in `club_works` because the occurrence model allows only one scheduled read. External reads have no canonical Work association. `club_reads` is authoritative for read lifecycle/history and selection outcomes; `club_works` is not a second history ledger.

Participation remains evidence-based: a read-specific discussion, reply, explicitly shared passage, or check-in establishes a historical participant. Silent readers may be undercounted. Spoiler projection still hides protected text, topic titles and shared-passage text server-side; unknown location fails closed. Journal shares remain explicit, and unsharing leaves the source Journal intact. Stats denominators remain participant occurrences, and historical aggregates use participants' current finalized ratings or fallback stars; a later rating edit may change history. Stats currently load completed Club Reads and matching ratings into memory, acceptable for ordinary Club sizes but a known scaling limit. No Club feature has moved personal progress, ratings, Journal ownership, canonical metadata, or file authorization into the Club domain.
